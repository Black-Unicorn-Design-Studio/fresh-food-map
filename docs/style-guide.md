# Style Guide — Fresh Food Map

**Status:** v1 · **Last updated:** 2026-09-13 · Covers visual design, UX writing, and code conventions.

What the app is and how it is assembled lives in the [TRD](./trd.md) — read it there; it is not repeated here. Conventions below are unmarked when they ship as described. *Not built* marks a rule written for something the app does not do yet: the rule stays (deleting one is how the mistake it prevents comes back), but nothing here describes an unbuilt thing as though you could go and look at it.

## 1. Design principles

1. **The map is the product.** Chrome stays out of the way; controls float lightly over the map and collapse when not needed.
2. **Provenance is recorded; trust is not graded.** Every listing is in the file because a person read its pull request and merged it, so the interface never sorts listings into checked and unchecked — there is no state to draw. Where a record came from stays in the data and on no screen: the ODbL obligation is discharged once for the collection, in the credit under the list, and never per listing where it could be read as a rank (§4, §5).
3. **Farmstand, not fintech.** Warm, sunlit, a little rustic. Avoid sterile SaaS blues and glassy gradients.
4. **Works in the parking lot.** High contrast, big touch targets, legible in bright sunlight on a cracked phone screen.

## 2. Color

Palette evokes produce and kraft paper. All pairings below meet WCAG AA (≥ 4.5:1 for text) — a claim that is now checked rather than asserted, and which failed in three places when it was: dark `backgroundSelected` was darkened to `#26301F` because `tint` on it computed to 4.47:1, input borders moved off `border` (1.32:1 against their own fill), and the disabled tag chip's opacity was raised because group opacity composited its label to about 2:1.

**Dark mode:** background `#1A1712` (warm, not pure black), surfaces `#262019`, accent surface `#1E2019`, text `#F2EDE4`, greens lightened one step (`#6BAE62`). Both modes ship; tokens live in one theme file — never hardcode hex in components.

**Filter chips:** a filter you have turned on inks `tint` on `backgroundSelected`; off is `textSecondary` on `backgroundElement`. **Every chip carries a `tint` border at 1pt, on and off alike** — the edge says "this narrows the list", not "this is on".

That is a deliberate revision of a rule this guide used to state the other way, and the revision is narrower than it looks. What was true, and still is: **green is the only "on" ink**, and nothing else in the interface colours a listing or a facet, so there is no second ink for a chip to borrow and be misread as. What changed: the *border* stopped being part of that ink. It was a kraft hairline when off and `tint` when on, which made a row of faint pills with one green one — and once `🕒 OPEN NOW` joined the row wearing a full neon edge, the tags beside it read as disabled rather than as its equals.

**The state is carried three ways and none of them is the border**: the fill (`backgroundSelected` against `backgroundElement`), the label colour (`tint` against `textSecondary`), and `checked` on a `switch`. That is what keeps this inside §6 — the rule was never "green means on" for its own sake, it was "meaning must not rest on colour alone", and it does not. Anything that takes `backgroundSelected` must still have an off state that surrenders it; the border is now exempt because it no longer claims anything.

**Two headings ink type `tint`** — the list heading's first word (§3) and the settings panel's title — and both are safe for the reason the rule is really about: a heading is not a control, takes no fill, and cannot be mistaken for a thing that is on or off. The settings title joined them deliberately; it measures 7.49:1 on the panel's `background` in light and 6.68:1 in dark, which clears AA for body text at a size that only needs 3:1. **The bar for a third is the same two questions**: can it be switched on, and does it take a fill. If either answer is yes it does not get this ink. Anything that *is* a control still answers to the sentence above. The list's `SORT` control used to wear the same pair and no longer wears either: **it does not change colour at all now**, and that settles an argument this paragraph lost twice. As a button it took the fill on any order but the default, which read as switched on over a list that has no on state — and, worse for §6, made its appearance the only visible thing saying which order was in force. Meaning in colour alone is the one rule this guide will not bend, so the colour went rather than the rule. It is drawn once: `backgroundElement`, a `tint` edge at a full point like every other filter on the row, and a `textSecondary` label — the same treatment `FILTER` wears at the other end, which is what makes the two read as a pair. Hold any future control to the surviving half of the old rule: nothing takes `backgroundSelected` unless it has an off state that surrenders it.

**Map pins:** one mark, used for every market — a green sprout on a white disc, 22px inside a 28px hit target, with the leaves *filled*. It was tried as the filter disc shrunk (the cream bar glyph on `tint`) and put back: at 22px over pale cream-and-green tiles a stroked mark reads as a scratch, where a filled leaf reads as a leaf. So the pin fills and the chrome draws, and they stay the same mark by construction rather than by resemblance — **the filter disc's two bars run along the two leaves' own diagonals**.

That is why both live in `src/constants/sprout.ts`: the web map inlines the leaves as SVG, `filter-toggle.tsx` builds the bars from rotated Views it derives from the same endpoints, and the native map needs a raster (a MapLibre `symbol` layer takes a registered image, not a path) generated by `scripts/gen-icons.js`. The first two import the geometry; the generator is plain JS outside the app's module graph and holds the only hand-carried copy. `test/sprout.test.ts` pins both halves — that each bar still spans its leaf's tip and base, and that the View placement is derived rather than retyped. Edit the shape there and rerun the script; never hand-edit `assets/images/pin-sprout.png`.

The native raster carries the light palette and cannot follow a colour-scheme change — a registered image is registered once. The web pin recolours itself in place. That is the price of a symbol layer.

**One mark for every market.** Pins answer *where the markets are* and nothing else. No per-listing state exists for a second mark to carry, and none should be invented for one. Nothing on the map depends on telling two pin colours apart, and the history is the reason to keep it that way — the previous two-colour scheme was 1.61:1 to normal vision and 1.22:1 under protanopia, the one surface where the never-colour-alone rule (§6) had been dropped, and it needed a legend to explain itself. Cluster bubbles would use `market.green.700` with white count text — clustering itself is *not built* ([TRD §9](./trd.md#9-budgets)).

**The summary card is a surface over the map, anchored to the pin it describes.** Pressing a pin opens `MarketCallout` (`src/components/market-callout.tsx`): the market's name as a level-2 heading, its town, whether it is open now *in words*, its tags, and `VIEW DETAILS` — **four** kraft rules closing that into the parts it has. **The week strip is not on it.** Seven discs is the most expensive row a 260 pt card has, and it answers a question — which days, across the whole season — that somebody opening a summary is not yet asking; they are deciding whether to tap through, and what decides that is which market, where, and what kind. The detail screen draws the same seven with the hours beside them, where there is room to read them. The fourth rule is the one between the tags and `VIEW DETAILS`, and it sits inside the tags conditional for the reason the town's sits inside the town's: an untagged market would otherwise draw two lines with nothing between them. **The card's root is `pointerEvents="none"`**, which is not tidiness — a `View` with a background is a touch target on both platforms whether or not anything wants the press, so as the card's paint grew it covered the `✕` and swallowed it. Handing every press to the controls that actually have handlers is the same lesson the map's floating chrome learned as `box-none`. It carries `Elevation.floating` — the dock's shadow, for the dock's reason — on `background` with a hairline border, and a fixed 260 pt width, which a card floating at a point needs and a card docked in a column does not: left to size itself, two adjacent pins give two differently shaped bubbles and a long name gives one wider than the phone.

**It reorients rather than hanging off an edge**, which took a different fix on each platform and is the kind of thing that looks fine until somebody presses a market near a corner. The web map portals the card into a `maplibregl.Popup`, which picks one of eight anchors from its own measured size — but it was picking before React had filled it, measuring an empty box, so it has to be asked again once the card is in. The native map draws the card as an ordinary absolutely positioned view over the map — **not** as an annotation, which is where three separate attempts at this went wrong: on iOS an annotation moves its drawing for an anchor, an offset or padding and leaves its touch frame behind, so a card against a screen edge was pressable half a card from where it was painted. `placeCallout` (`src/lib/callout-anchor.ts`) answers in pixels from the map's corner and is unit-tested: above the pin where it fits, below near the top, clamped inside the viewport rather than hooked to its own left or right corner within half a card of a side, the roomier side when it fits neither way, and never under the floating chrome — it takes `MapFitPadding` as unavailable for the same reason the camera does, because a card opening under the wordmark reads as a rendering fault. The card sits 20 pt clear of the pin on both — the pin is 28 across and centred on its point, so 14 clears it exactly and the rest is air the shadow needs.

**Where the table and the token file disagree.** `#4A8C42` (`market.green.500`) appears nowhere in `src/constants/theme.ts`. The sprout resolves to `tint` — `#2D5A27` light, `#6BAE62` dark — and the focus ring in §6 resolves to nothing at all: no rule in the repo sets one, so web focus is whatever the browser draws. `market.green.100` is light-mode `backgroundSelected` only; dark's was moved off it for contrast (above). The amber tokens are gone, along with the badge that was their only consumer. The two pin implementations also diverge: the web map recolours its sprout in place from `tint` and does follow the OS scheme, while the native pin is a PNG baked at `#2D5A27` by `scripts/gen-icons.js`, so native pins are light-palette-only. The disc under the sprout is a literal `#fff` in a CSS string rather than `backgroundElement`, and deliberately so — the pin has to hold against arbitrary map tiles, and a disc that flipped to `#262019` in dark mode would swallow it. That is the one hex left in a component, written down so it stays an exception on purpose rather than an oversight (§7). Recorded here rather than silently reconciled: picking the winner is a design change, not a docs edit.

## 3. Typography

Two-voice system — **Fraunces** (bundled via `@expo-google-fonts/fraunces`) carries every display moment; the system stack (SF Pro / Roboto / system-ui) carries body and UI text. Fraunces italic is the "handwritten aside" voice: season lines and italic turns inside headings. **The wordmark is not on that list any more** — it became the `ffm` monogram in Fraunces Black, and the splash follows it (§Brand mark), so the app no longer writes its own name in italic anywhere. Between those two changes the rule described season lines plus a single leftover, which is how a voice turns into an exception list.

| Role | Face / size | Usage |
|---|---|---|
| `display` | Fraunces Black 36–40 (and 15) | Screen headings, plus the one figure that is not one: the market count on both screens — at the foot of the map's filter card, and on its own line under the list's header band — takes Fraunces Black at 15 so the number reads as a number (§4). The list's is "Fresh, *from the land.*" at 40/46 — the app's only two-voice one, and now its only two-colour one. **`Fresh,` takes `tint`** and the trailing phrase keeps `text`, turning italic and dropping to 30 — which is also what keeps it on one line on a narrow phone. The green went on the italic first and was moved: on the trailing phrase it tinted the part the eye arrives at last and left the first word, the one doing the work at 40 in Black, in the same ink as every market name below it. On the first word the colour lands where the reader starts. Both sit on the masthead band (§4) at 7.10:1 and 13.86:1, past AA for body text let alone the 3:1 display type has to clear. A stroke on the letters was the other way to get green into a heading and is not available — React Native's `Text` has no stroke, and `-webkit-text-stroke` would be half a cross-platform component. It **does not change**: it used to become "Fresh, near you." once location was granted, which made the screen's title a status read-out, and a title is the one thing on a page that should hold still (§5). Whether the app knows where you are is said by the sort button and the line under it instead. "Add a market" and the detail screen's market name are roman 36 with no turn. The map has no display heading — its plaque is the wordmark (`aside`). |
| `title` | Fraunces SemiBold 22 | Market names on cards. |
| `overline` | System 11 / bold, letterspaced 1.2–2.5 | Kickers, chip labels, stamps — always UPPERCASE. Tag chips are the open exception: they take the metrics and keep sentence case (§4). |
| `body` | System 16 / medium (500) | `ThemedText`'s `default`. Never below 16 for body text. |
| `label` | System 14 / medium (500) | Card metadata (`ThemedText`'s `small`; `smallBold` is the same size at 700). |
| `caption` | System 12 | Attribution (`src/components/attribution.tsx`, 12/17). `soil.600`, sparingly. There is no `caption` type on `ThemedText` — the one consumer sets the size inline, and 12 otherwise belongs to `code`. |

It was "season lines and the wordmark, the only two", and the wordmark left: the plaque is the `ffm` monogram in Black, and the splash and the settings panel's title both set the name in Black to match it, so **the app no longer writes its own name in italic anywhere**. The settings title was italic briefly, on the argument that a panel introducing the app is a voice rather than a mark — sound in isolation, and it put the name in two faces in one app, which is what moving the splash to Black had just stopped. The italic turn inside the list heading is the same face a size up (`display`). Empty-state copy is plain body text, not this voice — *the warmth this row once promised there is not built* (§4). |

Line height 1.4–1.5 for body. Tabular numerals for hours (`08:00–13:00`).

## 4. Spacing, shape, and components

- **Spacing scale:** 4-pt base — `Spacing` tokens run `half 2 / one 4 / two 8 / three 16 / four 24 / five 32 / six 64`. Screen gutters 16 (`Spacing.three`); 12 is composed (`Spacing.two + Spacing.one`), not its own token.
- **Radii:** cards 12, buttons 10, chips full-round (`Radii.card` / `Radii.button` / `Radii.pill`). Consistent softness; no sharp corners, no pill buttons. Three tokens are the whole vocabulary, and there is no longer an exception to them — the 4 pt stamp corner went with the badge.
- **Elevation:** controls floating over the map get a soft shadow (`Elevation.floating` — `y=2 blur=8 @ 10%`); flat cards elsewhere with `kraft.200` hairline borders.
- **Camera padding:** a camera fitted to a box insets by `MapFitPadding` — top 128 (`Spacing.six * 2`), bottom 80 (`Spacing.six + Spacing.three`), sides 24 (`Spacing.four`) — so a framed pin never lands under the controls floating over the map: the wordmark at the top, the filter panel and `📍 NEAR ME` in the dock at the bottom. Both map files read that one token (`fitBounds({ padding })` on web, `padding` on `<Camera>` native), so moving a control is one edit rather than two cameras to remember.
- **Touch targets:** ≥ 44×44 pt, ≥ 8 pt apart.

### Core components
- **MarketCard:** overline (distance or town), Fraunces name, WeekStrip. Staggered fade-in on list load (70 ms steps, capped). One tap → detail.
- **WeekStrip:** seven circled day letters, market days inked solid green — the signature glanceable schedule. Screen readers get full day names in week order — "Open Saturday, Sunday" — rather than the letters or the raw schedule keys, and in the week's order rather than the order the record happens to list days in. That needed a role: react-native-web drops `accessible`, and a role-less View is `role=generic`, where a name is prohibited, so the label was discarded and seven bare letters announced in its place. `accessibilityRole="image"` maps to `role="img"`, which is nameable and children-presentational.
- **Detail header** (`src/app/market/[id].tsx`): the Fraunces name leads, then the market's tags — each pill followed by its one-line `TAG_DESCRIPTIONS` entry — with `FIND THE STAND` directly beneath. It is the only place in the app a tag explains itself in words. **No per-record source is displayed here, or anywhere.** The overline that used to carry it and the credit line that used to close the screen are both gone; `source` is still required on every record and still travels through the schema, the intake service and the batching agent, it simply has no surface. The database attribution is discharged on the list instead (`src/components/attribution.tsx`, the list's `ListFooterComponent`); §5 sets out why that is the surface able to carry it and a detail screen never was. Cards carry no source either, and nothing renders one as a stamp — the badge used to occupy this slot, so a stamp here would read as a grade to anyone who remembers it.
  - **No per-listing grade, ever.** Anything that ranks, badges, filters or sorts listings by how checked they are — including anything derived from `source` — is a review-blocker. Every market in the file was merged by a person, so there is no second state to draw ([TRD §3](./trd.md#3-what-merging-means)), and `source` is credit rather than a score.
  - Tag chips and day chips are pills (below) and never rotate. Nothing in the interface is tilted or stamped now; if something acquires that treatment, it is claiming to be a verdict.
- **The list's header is one tinted band, and it is the one tinted area in the app.** **It is ruled off top and bottom in `tint`, both at a full point** — the page's first drawn line and its last before the markets, in the green everything inside the band wears. The bottom was a kraft hairline for a while, on the argument that it was the market cards' own border drawn across and should hand off to the column rather than fence it out; matching the top won the better thing, which is that the band reads as one bounded object the way the row and panel inside it already do, instead of a stripe fading into the list. A full point rather than a hairline for the reason every green edge here is: at a hairline `tint` reads as grey at arm's length. `headerBand` runs `backgroundAccent` from the top of the page to just above the market count, holding the heading, the control row and the filter panel alike. It sat behind the heading and nothing else for a while, on the reasoning that taking in the control row would make the tint jump every time somebody pressed the disc and the panel opened — which is exactly what it now does, and the jump turned out to be the accordion rather than a fault in it: the header is one surface growing, not a stripe behind a title with loose chrome beneath it. The row and the panel stand on the tint in page colour (`background`), **inside** the content column rather than bled out to it, and together wearing a 1 pt kraft border **all the way round** (`PANEL_EDGE`, `border`) — the market cards' own border colour and weight, so the block is framed in the same tan the column below it is drawn in rather than in the band's green. The ring is drawn by two elements: the row takes the top, left and right, and the bottom belongs to the panel when it is open and to the row when it is shut. It was 5 pt down the left and right *only* for a while, with nothing across the top or bottom, and that is worth recording as a shape mistake rather than a colour one — a thick edge on two sides of an open-ended box reads as a shadow beside the controls, not as a border round them, with horizontal padding derived as `PANEL_INSET - PANEL_EDGE`. **That inverts what this used to optimise for, deliberately.** The block bled to the column's edges so its *contents* could sit on the market cards' 16 pt margin while its surface ran gutter to gutter; it now measures **8 → 382 on a 390 phone**, eight points wider than a card either side, with its contents 8 pt inside that. So neither edge lines up with the column any more, and the thing being aimed at is the gap rather than the alignment: `PANEL_GUTTER` is written as the amount of band left showing — 8, having been 16 and then 12 — because that is the number somebody measures off the screen, and the margin is derived from it (`PANEL_GUTTER - Spacing.three`, so 16 means no bleed at all and anything less spreads back out). The header then reads as a surface the controls stand on rather than a stripe they fill edge to edge. **Nothing between the row and the panel** — there was 8 pt, and with tint behind it that gap drew a green line across the middle of the block every time the panel opened, which read as a third thing arriving rather than as the row extending itself; meeting directly, the two are one shape, and the shape is drawn as one: the row rounds its top corners always and its bottom corners only while the panel is shut, the panel rounds only its bottom, both at `Radii.card`. The band bleeds to the content column's edges by cancelling that column's horizontal padding and putting it back inside, so the tint runs gutter to gutter while the words hold the same left margin as every card below them; `marginTop` cancels the column's top padding too, so it starts flush under the safe-area inset rather than floating below a stripe of page colour. On a wide screen it caps with the column at `MaxContentWidth` rather than running to the window — a masthead over the content, not a stripe across the browser. **No `aria-hidden` on the band**: it wraps the heading, and hiding a wrapper takes its children with it (CLAUDE.md). A `View` with no role and no text announces nothing anyway.
  - **The band closes on a hairline, not on a second tint.** There was a separate `backgroundAccent` rule under the controls for a while, bookending the header — a hairline first, then four points tall, the arithmetic being that `backgroundAccent` is 1.055:1 against the page, so a hairline of it is invisible and thickness is what buys a near-tone its legibility; it bled by the same negative margin the band does, measured identical at 375, 768 and — capped with the column — 800 inside a 1200 window. Then it widened again into a buffer, which is the form it survives in: the band's own `Spacing.three` of bottom padding. Every one of those widenings was an approximation of the tint simply running unbroken to where the list starts, which is what it does now. Once the same green ran down the control row's and the panel's sides, a rule under them was a seam drawn across a shape that was already one shape. What is left of the divider is the band's own bottom edge, a `StyleSheet.hairlineWidth` in `border`: the green ends against the same line every market card below is drawn with, and the list begins there. If that edge ever needs to be seen rather than felt, the colour is the thing to change, not the height.
- **FilterToggle** (`src/components/filter-toggle.tsx`): both screens collapse the tag chips behind a 44 pt disc, which is the whole target — it was 40 for a while, on the argument that at 44 the 24-unit glyph sat in 10 pt of padding a side and read as more disc than mark, with the 4 pt returned as `hitSlop`. The keyline settled it the other way: the active-filter dot is a square in the corner of a circle, and at 40 no inset keeps it inside that line without pushing it to the middle. The `hitSlop` lesson outlives the number and still binds anything that shrinks the paint again — **it is native-only**, react-native-web's `Pressable` dropping the prop entirely, so a disc smaller than its target is 44 on a phone and its own size in a browser. It clears WCAG 2.5.8's 24 comfortably and misses this guide's own 44, and it is recorded here rather than quietly fixed because whether to take the disc back to 44 is the design call §4 already weighed and settled the other way. Shrinking a control's paint is fine, shrinking its target is not, and the two are the same number only by convention — the chips and their counts were otherwise the first thing under the heading on either one, ahead of the controls people actually reach for. It docks bottom centre on the map, above `📍 NEAR ME`; on the list it **leads the single control row** from the left gutter, opposite `SORT` held against the right edge — the only other control in that row, `🕒 OPEN NOW` having moved inside the panel to lead the chip row (below). The count is not in that row on either screen, and the two screens put it in different places: at the foot of the card on the map, and on the list on its own centred line below the header band, where it can be read with the panel shut (§4, below). Only the map's is `floating`: the shadow is off by default because the list is a flat page, where a lift on one control and not its neighbours reads as a mistake — the same split `Wordmark` makes for the same reason. **The list labels it `FILTER`; the map pulses instead** (§4's motion rules), and the split is the room each has — the list's row is half empty and a bare sprout asks the reader to already know what the mark means, where the map's dock is three controls stacked over the tiles the screen exists to show. The word has been round the loop: `FILTER` first, then `SEARCH` when the panel gained a search field — on the grounds that a label naming half of what is behind it is worse than none — and `FILTER` again now. What settled it is which half the reader arrives wanting. The panel is a search box over a row of tag chips, and both narrow the same list; the disc is the thing you press to narrow it, and the row it sits in already carries `SORT`, the other verb for rearranging what is below. `FILTER` is that verb; `SEARCH` named the field rather than the control. The spoken name still covers both, and still contains the drawn word (below). The word takes the overline's treatment **including its uppercasing**, because what it sits beside is `SORT` — two labels on one row, and a sentence-case word beside an uppercase one reads as a different kind of thing rather than the other half of a pair. `🕒 OPEN NOW` was the third of the set until it moved into the panel, and it keeps the same treatment down there, where the row it now leads is sentence-case tag chips (below).

  **The visible word is no longer the accessible name.** It used to be, on the reasoning that one string cannot drift from itself; but the spoken name has to cover everything behind the disc and the visible one has to fit a row beside two other labels, and making one string do both is how a panel ends up announced as half of what it holds. So the spoken name is **"Search and filter"** on both screens, with the active count appended rather than substituted ("Search and filter, 2 active"), and what stops the two drifting is a rule instead: the visible word must appear inside the spoken name, which is what WCAG 2.5.3 asks and what `FILTER` inside `Search and filter` satisfies — containment there is case-insensitive, so the drawn word may shout while the spoken one stays a sentence. Anything that would not fit that sentence does not belong in the `label` prop. It inverts the pin: the mark in `background` on a `tint` disc, the pair the wordmark and the favicon already share (§2), so all three stay a set in both themes. The glyph is not the pin's path — two bars and a stem built from Views, laid along the diagonals the sprout's leaves run on and placed on its 24-unit grid, a hand copy of those coordinates rather than a third consumer of `src/constants/sprout.ts`: that file is the pin, mirrored in `scripts/gen-icons.js` because a MapLibre symbol layer takes a raster, and this glyph is chrome that is never rasterised, so it has no regeneration step to join. The panel is a wrapping row of chips on both screens, but the two hold it differently, and the difference is the room they have. The latter sends people to the submit form's coordinate inputs, which do not exist here; every failure has to name something the reader can actually do next, and on this screen that is "search by market name" or "try a nearby town". There is a test that the place words never mention coordinates.
  - **Search sits above the chips, and is the card's first control.** Typing a name reaches one market faster than any combination of facets, so a reader who knows what they want should not have to read four of them first. It matches over the market's **name and address** — the two fields a card actually shows, since the town on the overline is a slice of the address — because a result nobody can account for reads as a bug in the search rather than a fact about the market. Every whitespace-separated term must match, so more words mean fewer markets: the same promise the chips make, and the opposite would be a search that widens as you get more specific. Order is irrelevant ("athens farmers" and "farmers athens" are one query), matching is case- and accent-insensitive, and an empty query is not a filter. `searchMarkets` in `src/lib/markets.ts`, and its `normalize` call is guarded because Hermes has shipped without it — a search box that throws is worse than one that cannot see past an accent.
    - **`NAME` is not place search, even though they share a box.** `NEAR` turns a place name into coordinates and needs a geocoder ([PRD §3](./prd.md#3-core-user-stories)); `NAME` narrows a set already in hand and needs nothing — it works with the radio off, the network down and the dataset bundled. Do not let the two collapse into one line item: the offline half is the one that would quietly be lost.
    - **The empty state has to name the search first.** A query that found nothing is the narrowest thing the reader did and the likeliest to be a typo, and it is the one case where "No markets here yet" would be a lie about the dataset rather than a fact about it. That branch was missing when search first landed and the lie got told; the ordering in `ListEmptyComponent` is what stops it.
    - The counts on the chips are computed against the searched set, so a chip promises what the tap will give you *given what is typed* — the same rule that already binds them to `🕒 OPEN NOW`. **On the map the search feeds the camera as well as the pins**: `found` narrows before `shown`, and `shown` is what `boundsAround` frames, so `📍 NEAR ME` cannot fly to a market the search has excluded. Both are memoised on their inputs, because a fresh array identity rebuilds every marker on the web map.
    - On the map the field is first in the card too, which puts it at the card's **top** — the card sits above the disc there rather than below it, so first-in-source is furthest from the thumb. One habit across two screens was worth more than optimising each for reach, and the chips it pushes down are the things you reach for less.
  - **No selection is not a filter.** Zero chips on shows every market — `filterByTags` returns the list untouched (`src/lib/markets.ts`). There is no "All" chip and no "clear" button: the cleared state *is* the empty selection, and clearing is turning chips off.
  - **More chips means fewer markets.** Selections AND together. A second filter that widened the list would contradict what choosing it means.
  - **Counts are conditional, so they can be trusted — and they still are, unprinted.** Each chip's number is computed with every *other* narrowing already applied (the other tags, the search, and `🕒 OPEN NOW`), so it promises what the tap will actually give you rather than how many markets carry that tag in the abstract. It was not always so, and a chip could read `Producer-owned 2` over an empty list — a count on a filter promising what the filter cannot deliver, which is the one thing it must never do.
    That arithmetic did not become decorative when the number left the chip. It still decides which chips are disabled, and it is still what `accessibilityLabel` speaks. **Keeping it in the spoken name is deliberate**: a dimmed, dashed chip tells a sighted reader why it will not respond, and `Indoor, 0 markets` is the only thing that tells anybody else. Break the conditional arithmetic and you break the disabled state, not just a caption.
  - **A zero-count chip dims and goes dashed; it never disappears.** `disabled`, a dashed border, and 0.9 opacity — not the 0.45 this once specified. Opacity here is *group* opacity, compositing the label onto the page along with the chip, and 0.45 put the count at roughly 2:1 (§2) in what is the default state of two chips on this dataset rather than an edge case. So the dim is deliberately slight and carries none of the meaning alone: the dashed border, the count reading zero, `aria-disabled`, and the chip not responding all say it independently. Chips stay put because a panel that loses them as you select jumps under your finger, and a hidden facet reads as a facet that doesn't exist rather than one that's empty here. A *selected* chip is never disabled, or you couldn't undo it. (Tagging trails the dataset: 2 of the 8 markets carry a tag at all, so `Indoor`, `Organic focus`, `Grocery store` and `Donations available` are not drawn at all today — `availableTags` offers only the tags the data actually uses, and a tag nothing carries can only ever return an empty list. A tag that is empty *given the current filters* is a different case and still shows, greyed at zero: that one can change while you look at it. The fix for the first is tagging markets.)
  - **Green means selected, and nothing else inks a chip** (§2). `MARKET_TAGS` holds facts about a market and no grade, and there is no grade anywhere for a chip to acquire — so a filter like this can never come to mean "checked".
  - **A box draws the chips as a group, on both screens.** The search box with its radios answers "which market"; the chips answer "what kind" — and read straight down, the mode radios and the tag chips are both small bordered words in a row, so the eye grouped them. A 1 pt rule between the two was the first answer and drew only the boundary; a box around the chips draws the thing, because a line says "these are apart" and an edge says "this is a set", and it was the second that was missing. **The edge is `tint`, and a full point** — the same green the chips inside it wear, for the same reason: it says "this narrows the list", not "this is on". A hairline was right while the edge was kraft and reads as grey once it is green, which is the defect that took the chips off hairlines first. **Square corners, written as `borderRadius: 0` rather than left to the default** — every other bordered thing in either panel is a pill or a rounded field and is something you press, so a rounded box this size would read as the largest button on the screen; spelling the zero out also means a reader skimming for a missing radius finds a decision rather than an omission. Not hairline: inside a card that already draws a hairline border, a sub-pixel edge reads as a rendering artefact. It spans exactly what the rule spanned — the panel's content width, inside the card's own padding rather than bleeding to its edge — and carries a `marginTop` of 14 on top of the panel's own 8 — 22 in all — so the search block and its radios end and the chips begin on a clear beat rather than the same gap that separates a field from the pills belonging to it. It was 12 first, which read as a slightly generous version of the panel's own rhythm rather than as a break in it; the margin is written as `Spacing.one + Spacing.two + Spacing.half` rather than collapsed, so the 4 it started at and the 10 it grew by both stay legible. **It carries no `aria-hidden`, and the rule it replaced did** — a leaf and a wrapper are not the same thing, and the props came across with the markup: hiding the wrapper took all four chips out of the accessibility tree on both screens while leaving them in the DOM, and a violations-only axe run said nothing — axe raises this as an *incomplete* (`aria-hidden-focus`, since the chips are focusable), not a violation, which is one reason §6 says to read the role engine. A `View` with no role and no text announces nothing anyway, so there was never anything here to hide (see CLAUDE.md). **The list gets the same box**, and it is no longer an exception to a panel that draws nothing: the list's panel is a drawn surface now — page colour, a 1 pt kraft (`border`) edge continuing the ring the control row starts, `Radii.card` on its bottom corners while it is open, and `Spacing.three` of padding under its contents — so it reads as the control row extending itself rather than as a gap the rows make. The box still draws a group *inside* that surface rather than a second surface under it: no fill, no radius, no shadow, so the accordion is still not a card.

  - **The map shows its count too, at the foot of its card.** It was off-screen there for a long time, spoken but not drawn, on the grounds that the chips carried their own numbers — and when those numbers went, nothing on the map said how much of the dataset you were looking at. A pin vanishing is silent in a way a row leaving a list is not, so the map needed it more than the list did, not less. Last in the card because it reports on everything above it: the search and every chip. There are **three** off-screen regions there now, not one: the count sentence in the first, the staleness note in the second, and the summary card's announcement in the third. They are deliberately separate nodes, because `role="status"` carries an implicit `aria-atomic="true"` and a region is therefore re-read whole on any change — put both strings in one node and the stale-data warning is spoken again on every chip press for as long as the refresh stays broken. Splitting them is the only fix available: `aria-atomic` is mis-wired in react-native-web 0.21.2 and never reaches the DOM, so the implicit value is the only one there is. Nothing is said twice, because the figure drawn in the card is `aria-hidden` paint.
  - Count and empty state answer to the filter. **The count is drawn in words and spoken in more of them**, from two separate nodes. **The two screens now put it in different places, and that is a decision rather than drift.** On the map it is centred at the foot of the filter card, which is the only surface that screen has. On the list it sits on its own line between the header band and the first card, centred under the band's bottom edge and evenly spaced from both — `Spacing.three` above and below, set by a matched `+`/`-` margin pair on the row rather than a single `marginTop`, which would have pushed the whole column down instead of moving one line inside it — a caption on the list rather than a footnote to the controls. It was on the left gutter first, which put it in line with the cards and reading as the first of them; centred under a band that runs the full column, it reads as a caption on everything below. So the two screens agree on how the number looks and differ only on where it sits in the stack. It lived at the foot of the list's panel for a while, which put it in the one place it could not be read from: shut, which the panel is most of the time. It reads `8 markets` — `1 market` when one is left — **with the figure set in `Display.black` at 15 and the word left in the body font**: it is the one number on either screen read as a number rather than as a label, and Fraunces gives it the weight to be found without making it a second heading. 15 against the `small` text's 14 beside it — one point up, because Fraunces runs smaller than the system face at a shared nominal size. The map takes the list heading's face, Fraunces Black, having no display heading of its own to take one from. That used to be a choice between two faces — the wordmark was Fraunces *Italic* when this was written, so borrowing named which of the two it borrowed from. The plaque is Black now as well, so the two simply agree and there is nothing left to choose. A nested `Text` rather than two siblings, so the pair shares a baseline and wraps as one phrase; the sentence, "1 of 8 markets shown", lives in an off-screen `Text` styled `srOnly`, carrying `role="status"` with `aria-live` *and* `accessibilityLiveRegion`, while the drawn figure is `aria-hidden`. It has been three things: `1/8 markets` beside the sprout disc with the sentence in an `accessibilityLabel`; then a bare `1` at the right of the control row; now this. Each move fixed something real. The `aria-label` was wrong because a live region announces its changed **contents**, which a label does not replace — Chromium's tree showed the region named "8 of 8 markets shown" with a StaticText `8` still under it, leaving what a screen reader says undefined. The bare numeral was wrong because `1` means nothing away from the control it was pinned beside, and it was pinned there by an auto margin that a five-child row could not afford anyway. `8 markets` survives being read on its own, which is what lets it sit centred under a box rather than beside anything.
    - **The spoken region lives outside the panel, and that is load-bearing.** The drawn count is inside a panel that is shut most of the time, and it is worth being exact about why that matters per screen. On the list nothing outside the panel changes the number by hand any more — `🕒 OPEN NOW` moved in among the chips, and the sort button reorders without narrowing, so all four of its orders leave the figure alone. That used to be the list's own argument and is not any longer, which leaves both screens carrying the same one: the mounting rule, plus a runtime refetch and the tags shared from the other screen through `useFilters`, all of which move the figure while the panel is shut. So it sits at screen level on both — on the list beside the warning line, on the map in its own off-screen node, beside the ones carrying the staleness note and the summary card's announcement. Mounted unconditionally either way, because a region inserted along with its text is not reliably announced.
    - **On the list the count is visible whatever the panel is doing**, on its own line between the band and the first card. That reverses a trade this paragraph used to defend: the number moved into the panel because it is a property of the filters and because the row it left could then hold four controls on the narrowest phone. Both halves stopped applying — the row is two controls now, and a figure that reports on the filters is still read by somebody who has not opened them, which put it in the one place it could not be read from. The map keeps it at the foot of the filter card, that screen having no other surface to put it on. A screen-reader user is unaffected either way: the live region never moved into the panel in the first place.
  - **Both surfaces share the component, and now the arrangement.** Same chips, same `layout="wrap"` — word-width chips breaking where they fall, and **centred**, because chips sized to their own labels leave a short last line almost every time and flush left that reads as a row which failed to fill rather than as the end of a set; centred, the ragged edge is symmetrical, and the block lines up with the reader-relative pair above it and the market count below — inside a panel that stays closed until the sprout toggle (`src/components/filter-toggle.tsx`) opens it — so neither view can narrow to something the other cannot reach, and neither has a filtering gesture the other lacks. A filter added to one is added to both, or the two views disagree about what exists.

  **Where the two chip rows disagree.** `tags.ts` keeps labels in sentence case on the grounds that "the chip styling does the shouting", but `tag-filter.tsx` applies only the overline's metrics (11 / 700 / 1.2 letterspacing) and no uppercasing — so on the list `Producer-owned` sits in the same wrapping row as `🕒 OPEN NOW`, wearing the identical metrics in sentence case directly beside it, a few pixels under the control row's two uppercase labels — `FILTER` and `SORT` (the four sort options escape it too: sentence-case body text at 15, because they are a list to read rather than a rail of chips). One filter area, two type treatments. Recorded rather than quietly reconciled, as in §2: settling it is a design call. Whichever wins, both rows take it together, and if uppercase wins the spoken form stays sentence case — `accessibilityLabel` already says `Producer-owned, 2 markets`.
- **Submit form** (`src/app/(tabs)/submit.tsx`): the third tab, and the only place the app writes anything. It is a form, not an account flow — nobody signs in, the screen says so in its opening line, and there is no session for any surface to display. The rules it is built on:
  - **The submit gate is spoken, not printed.** "Needs a market name, a street address and a location." is `srOnly` — off-screen, never `display: none` and never `aria-hidden`, both of which would take it out of the accessibility tree along with the pixels — and it stays the disabled button's `aria-describedby`. The asterisks tell a sighted reader which fields are required; this tells anyone who cannot see the button dim why it will not take a press. The gate was once written down only in a code comment, which is the gap this closed, so hiding the text visually must never reopen it.
  - **Required fields wear an asterisk, and the asterisk is drawn from the same flag that sets `aria-required`.** `field()`'s `required` argument does both, so what a sighted person sees and what a screen reader is told cannot drift apart — which is the ordinary way an asterisk goes wrong. The glyph itself is `aria-hidden` on all three of the props that need saying (§6): the label node is what `aria-labelledby` points at, a hidden descendant is left out of the name it computes, and so the field is announced "Market name", not "Market name star". The requirement travels as a state instead. It is `textSecondary`, never `danger` — red is errors and destructive actions only (§2), and an empty required field is neither.
  - **Forgiving on purpose.** Three things gate the button: a name (3+ chars), an address (5+), and a coordinate pair. Days, hours, tags, website and the reviewer note are all optional. A market submitted with no hours is a market a reviewer can finish; a market nobody submitted because they didn't know its hours is simply gone. Resist adding a fourth required field — each one is markets lost, and the reviewer is right there ([TRD §4](./trd.md#4-the-submission-pipeline)).
  - **Nobody types a latitude.** The coordinate pair is required — the feature schema needs a Point geometry — but it was the field costing the most submissions, because it asks for something people simply do not have. `🔎 Find it from the address` geocodes what is already in the address field and fills both (`src/lib/geocode.ts`); `📍 Use my current location` remains for the case where you are standing there. Three rules hold this shape. It is **never disabled for a short address** — pressing it says what to do instead, and a greyed control explaining nothing is the dead end the button replaces. The result is **shown and left editable**, credited inline as "Found via OpenStreetMap", with "Not right? Edit the numbers above." under it: a silent fill puts a wrong coordinate into a pull request looking exactly like a right one, and a complete-looking record is what survives a skim. And the outcome lands in **its own already-mounted live region beside the fields**, not in the notice at the foot of the form — filling two inputs makes no sound, and that notice is 600 px away on a phone (§6).
  - **Per-day hours are behind a switch, and the common case does not pay for them.** Most markets trade the same hours every day they trade, so one shared pair stays the default and the whole question is hidden until a day is actually picked — before that there is nothing to vary, and asking would be a question about an empty set. Turning the switch on seeds every selected day from the shared pair, so nobody meets seven blank boxes having just typed "8 to 1"; turning it off keeps what was typed rather than clearing it, because an accidental tap must not silently delete somebody's work, and `hoursFor` ignores the map while the mode is off so nothing stale can reach the wire. It is a **`switch`, not a disclosure `button`** — the distinction `FilterToggle` sits on the other side of (§6) — because this changes what gets submitted rather than only what is drawn. Every revealed input names its day (`Saturday opens`, never a seventh `Opens`): seven identically-labelled pairs are indistinguishable to a screen reader, and that is precisely where a swapped pair becomes a wrong time in a committed file. A day whose pair is left incomplete is dropped from the payload rather than sent half-filled — hours are optional, so an unfinished day is a gap a reviewer closes, not a validation failure nobody asked for. The schedule is then **normalised to week order** (`scheduleFor`, off `DAY.options` rather than a second list to drift from), so tapping Saturday before Wednesday and Wednesday before Saturday produce identical JSON: a data pull request should diff on a real difference or not at all, and a reordered array is not one.
  - **Ask in the reader's words, not the schema's** — `WHICH DAYS?` and `ANYTHING TRUE OF IT?` over `schedule` and `tags`. Overline treatment (§3), so the emphasis is type rather than tone.
  - **Day chips:** seven letter circles, the same alphabet and order as the WeekStrip, so what you fill in looks like what you'll see on the card. On fills `tint` and inks the letter in `background`; off is `backgroundElement` behind a `border` hairline. 40×40 at `Radii.pill` — deliberately not the tag pill's shape-and-size, because these compose a schedule rather than narrow a list. One `open`/`close` pair applies to every day selected — until `☐ Different hours on some days` says otherwise (below). Each speaks as `Open on Monday`: the group caption is folded into every chip because VoiceOver often skips group boundaries in form navigation, and seven bare letters ("M", "T", "T"…) are indistinguishable read aloud.
  - **Tag chips borrow the filter panel's vocabulary, its order and its look** — `ORDERED_TAGS`, `TAG_LABELS`, `Radii.pill`, `tint` on `backgroundSelected` when on — but carry no counts and are never disabled. On the list a tag asks a question about the dataset; here it states a fact about one market, and there is nothing to count.
  - **The honeypot is invisible, not hidden.** It sits off-screen (`left: -9999`) rather than under `display: none`, which bots read; it declares `accessibilityElementsHidden` and `importantForAccessibility="no-hide-descendants"` for native, `aria-hidden` for web because react-native-web drops both of those (§6), and `tabIndex={-1}` everywhere, so no keyboard or screen reader can land in it, and `autoComplete="off"` so no password manager fills it. It writes to a ref, never to state — a keystroke in a decoy must not re-render the form. The timing signal follows the same discipline: `Date.now()` is stamped in an effect, never during render, or a re-render moves the clock the check reads from. Never give this field a visible label, a placeholder, or a name that invites autofill.
  - **No third-party anti-spam.** The honeypot and the elapsed-time stamp are the entire client-side defense; everything else belongs to the service. No CAPTCHA, no fingerprinting, no analytics — a form that tracks you to prove you are human is a worse trade than a reviewer skimming one spam row.
  - **The public-content warning opens the form, and the note field points back at it.** The note is the one free-text field and `server/batch.ts` quotes it verbatim into the pull request body, so somebody has to be told before they type. It was a caption under that input once — precise, and read only by whoever reached the last field. Now it is the tail of the opening line, hung off the sentence that says the market gets published: "published as open data anyone can reuse — please leave out personal details." Publication is the reason for the ask, so the two belong in one breath, and everyone meets it first. Moving copy up a screen normally costs the per-field association, and here it does not: `field()`'s `describes` argument points the note at the intro's id, so the input keeps `aria-describedby` on the web and `accessibilityHint` on native without the sentence being written twice. That mattered more than it looks — Tab and the VoiceOver rotor jump control to control and never pass a paragraph, the intro sits about 700 px above the note on a phone, and on native the hint was the only carrier there has ever been. `describes` is not `caption`: a caption renders its own text under the input, this borrows text that is already somewhere else. One trade is left standing on purpose — the copy no longer says the words "becomes public", so the em dash carries that inference.
  - **Say what happens next, every time.** Success reads "Thanks — it is queued for review. A person reads every submission before it appears," not "Submitted." A rate-limit refusal names the other route (open a pull request). Field errors land under their own input in `danger` with the input's border switched to match; the notice line stays general.
  - **A form that cannot post is replaced, not disabled.** With `EXPO_PUBLIC_INTAKE_URL` unset the whole form gives way to a card explaining the pull-request route — which is where every submission ends up regardless. Any future write surface takes that shape: name the manual path rather than showing controls that go nowhere.
- **EmptyState:** friendly illustration + action, e.g. "No markets here yet — know one? Add it." Spec, not a component: the copy ships as inline text in the list's `ListEmptyComponent` — two strings, empty-area and empty-filter, plus a loading line — with neither illustration nor action button.

### Motion & texture
- **Load-in cascade:** list cards and detail sections fade in from below (Reanimated `FadeInDown`, ~360–380 ms), staggered in 70–90 ms steps and capped (≤560 ms total delay) so long lists never feel slow. Still the one *decorative* moment; skip scattered micro-animations.
- **The filter accordion is the one motion that is not decoration**, and that is the bar anything else has to clear. Opening the list's panel moves every row below it, and without the transition the list jumps by the panel's height in a single frame — visually the same event as the content changing underneath you. The animation is what distinguishes "this moved" from "this is different now", so it earns its place; a fade on a button would not. `FadeIn` on the panel, `LinearTransition` on the list, both skipped entirely under `useReducedMotion` rather than shortened.
- **The disc's attention pulse is the second motion that clears that bar, and it clears it lower.** A UX review found the map's sprout disc was not reading as the place to start — a bare mark over tiles, with the labelled `📍 NEAR ME` beneath it sharpening the contrast. The list answered the same complaint with a word; the map declined it, its dock being three controls deep over the one thing the screen exists to show. So three seconds after you arrive on the map, a dark green ring pulses twice around the disc, rests six seconds, and does it again — for as long as you stay on the screen without pressing anything in the dock. It has been white, then `tint`, then `highlight`, then white, and is `tint` again — and the objection to white kept being the one that was right: the tiles are pale cream and green, so a white ring has very little to sit against once it clears the disc, and the motion ends up carrying the hint on its own. The disc's cream keyline was meant to rescue it, the ring reading as that line lifting off the mark, and it does at the first frame and not at the last — which is the frame that has to land. `tint` is the disc's own colour, so the ring reads as the mark itself expanding and holds against pale tiles at every radius. It needs no fixed token either, which is why `mapOverlay` is gone (§2): the disc it grows from is `tint` in both themes, so a themed green stays legible over a map that never darkens — exactly what a themed white could not do. Opacity and scale peak on the same value either way, so the ring is invisible while it hugs the rim and resolves only once it has expanded clear of the disc. **It recurs, and that is a deliberate step away from strict WCAG 2.2.2.** It was a single burst first, chosen precisely to sit inside that criterion: motion that starts on its own and runs past five seconds needs a way to pause, stop or hide it, and content that stops itself inside five is exempt. One burst was exempt; a recurring one is not, and the honest thing is to record that rather than argue the rests count as stopping. What stands in for the mechanism is that any press in the dock ends it for the session, that leaving the screen stops it, and that a reader who has turned motion off never sees it. **If strict conformance matters more than the recurrence, the fix is a cap — a few cycles and then done — not a longer rest.** The burst stayed at two because one reads as a glitch and three as nagging: 2.2 s of movement in every 8.2 s of cycle, measured at peaks 1.1 s apart and bursts 7.1 s apart.

  **Tied to screen focus, not to mount.** Both tabs stay mounted, so a plain effect started the three seconds when the *app* did — the hint fired once, early, whether or not the map was the screen you were looking at, and being a single burst that was the only time it ever fired. Open the app, glance at the list, come back, and there had never been anything to see. `useFocusEffect` starts the clock when the map does and stops the pulse when you leave, so it never runs unseen on another tab. It animates `opacity` and `transform` only, so it never touches layout, and it carries `pointerEvents: 'none'` — a ring that swallowed the press would make the control harder to use at the moment it is asking to be pressed. **Be clear about what it buys:** a pulse points and does not explain. Somebody who looks at a pulsing sprout still has to press it to find out what it does; the hint wins attention, not comprehension. If the review comes back saying people looked and still did not press, the answer is the word, not a louder pulse.
- **No auto map movement:** the camera moves only in answer to something you did — with one exception worth naming rather than leaving to be discovered. The dataset is refetched from the CDN at runtime, and a refresh carrying genuinely different markets hands back a new array, which the fit rules read as a changed set and re-frame for. React Query's structural sharing keeps the old array when nothing changed, so an unchanged refresh moves nothing. The first render is not a fit either: the screen opens on `DEFAULT_CENTER` at zoom 3.5, the whole country, because that render is the one the last-inputs comparison is seeded on and nothing has changed yet. **`📍 NEAR ME` frames the radius it searched**, not the markets it found — framing the results would zoom to whatever happens to be nearby, so two markets a street apart would fill the screen and hide that the filter looked twenty-five miles out; the box is also what makes a widened radius visible rather than merely announced (`boundsForRadius`). It is checked first, ahead of every other framing rule, because the chip carries its own position and a box drawn round the surviving markets would answer a different question from the one the radius asked. There is no longer a "no location yet" fallback behind it to guard against: the ordinary fit runs on whatever is shown whether or not anybody has located themselves, and a typed place survives as a rule of its own — the point and the nearest market to it — rather than as the precondition the whole camera used to hang on. Place search still frames the town together with the nearest market to it, since a typed place is an origin and the nearest market is however far away it is. Changing a tag re-frames whether or not anybody has located themselves or typed a town, because a box computed before the filter crops out a market the chips still count. That last clause is newly true: the bounds used to be computed only when a place had been searched, so with no origin the camera never re-fitted at all, and narrowing to two markets in Georgia left the map wherever it had last been panned — empty country beside a panel claiming two results. The exception is `📍 NEAR ME`: while the radius filter is on, a tag press deliberately leaves the camera alone, since the four numbers would be identical and only the array new, and the map would ease back to the radius and take the reader's own panning with it. Tapping a pin opens that market and leaves the camera where it is. **It respects `prefers-reduced-motion`**, which for a long time it did not. Both map files read it and pass a zero duration — `fitBounds` and `easeTo` on the web, `<Camera duration>` on native — so the frame still changes and simply arrives rather than travelling. Suppressing the fit instead would leave the map showing somewhere the filters no longer describe, which is a worse answer to a request about animation. One trap, paid for once: the duration is *spread in* rather than passed as an explicit `undefined`, because `easeTo({ duration: undefined })` is not the same as omitting the key — MapLibre reads the property as given, and the arithmetic downstream yields a null transform that surfaces as `Cannot read properties of null` inside `_calcMatrices` mid-ease. The options object is memoised too: both camera effects depend on it, and a fresh object per render re-runs them on every render, which is the fighting-for-the-camera failure arriving through a dependency instead of an inline literal.
- **Kraft grain (web only):** a fixed full-viewport fractal-noise overlay at 5% opacity (`src/global.css`), pure CSS data-URI — atmosphere without assets or requests.

## Brand mark
The "ffm" monogram — lowercase Fraunces Black with the crossbars running together like a hand-carved stamp. App icon: cream mark on `market.green.700` inside a double keyline — a crate-stamp keyline, the same hand-carved language as the monogram. All icon/splash/favicon PNGs in `assets/images/` are generated by `scripts/gen-icons.js` from the bundled Fraunces TTF — regenerate, never hand-edit.

**Splash:** the sprout disc over the app's name in Fraunces Black — the disc because it is the one shape a reader meets on every screen, and the name in the logo's own face so the first screen and the plaque in the corner of the map are the same lettering. The disc is drawn to a fixed fraction of the canvas (160 of 600) so that `imageWidth: 220` in `app.json` renders it at **58 pt**, the size it was when it sat on the launch screen alone; tying it to the canvas instead put a 140 pt circle there, and a later fix tied it to the wrong number and left it at 76.

**A device that has carried an older build keeps showing its launch screen.** Change the splash and that device plays the old one at full opacity and then cross-fades to the new one — two splash screens, which reads as a bug in the app and is stale device state. It is stubborn: it survived an uninstall-and-reinstall, a wipe of `Library/SplashBoard/Snapshots/*`, a simulator reboot and a Metro `--clear`. The same binary on a simulator that had never had the app showed one splash, correct from the first frame, which is what located it. So verify a splash change on a device that has not held the previous build, and confirm what shipped with `assetutil --info` on the built `Assets.car` rather than trusting the screen.

## 5. UX writing

- Tone: warm, plain, brief. "Find markets near you", not "Discover local produce experiences".
- Sentence case for anything read as prose — headings, links, notices, empty states ("Add a market"). Uppercase is a type treatment, not a voice: it belongs to overlines, chip labels, and stamped button labels (§3 `overline`), where it stays two or three words long.
- Say "market" not "location/POI". If a listing's source is named, name it in a reader's words — "from OpenStreetMap", "community-submitted" — as credit for where the fact came from, never as a hedge about whether it is true. *Not built:* no surface names one now (§4). The rule stays because `source` is still on every record, so a surface for it can come back.
- **Publishing *is* vouching.** A record is in the file because a person read the pull request and merged it, and there is no second state it can earn ([TRD §3](./trd.md#3-what-merging-means)). Copy must never imply a further checking step — no "not yet verified", no "pending review", nothing waiting on a market the app is already showing. Copy describing the check describes a review someone did on a pull request, never a button someone pressed.
- **Tags name facts, not claims.** A tag has to be something a reader could confirm from the market's own listing — that is the bar `src/constants/tags.ts` sets, and it is what keeps a facet from hardening into an opinion about the market. Labels are sentence case and two or three words (`TAG_LABELS`); each carries one plain line for the detail screen (`TAG_DESCRIPTIONS`), because a tag nobody understands is noise in the panel. The vocabulary is closed on purpose: adding a tag is a pull request against that file, which is the right amount of friction for a word everyone has to share.
- Say **reviewer** for the person who reads a pull request and merges it. That is the only human role here, and the word names a job rather than a grant: whoever holds commit rights is a reviewer while they are reading a diff, and nobody is one otherwise. Don't reach for "curator", "admin", "moderator" or "the team" — none of them exists here, and each implies a permission system the project deliberately doesn't have.
- Ask for a submission plainly and promise only what actually happens: "No account needed. The market is reviewed by a human and published as open data anyone can reuse — please leave out personal details." Never "instantly", "approved" or "goes live" — a form queues a fact for review; merging is what publishes it. The success notice is the other half of the same promise and keeps the fuller wording, because by then the thing has actually been queued: "Thanks — it is queued for review. A person reads every submission before it appears."
- Errors say what happened + what to do: "Couldn't load new markets. Showing saved data — pull to retry."
- Attribution (legally required), two surfaces discharging two different obligations, neither interchangeable: "© OpenStreetMap contributors" in the map's own control credits the *tiles*; the ODbL line on the list (`src/components/attribution.tsx`) credits the bundled database, which ships inside the app. It sits on the list rather than behind a tap because OSMF guidance is explicit that attribution must not require interacting with the work to see it — which is why the per-record credit that used to sit on the detail screen could not have discharged this obligation even while it existed. The same component carries the AGPL §6(d) source link, for a parallel reason: a browser loading the web build has received a copy of the program, so directions to the source have to travel with it rather than sit in a README. This is a licensing term, not a trust display, and it survives the removal of any trust display — a sweep for grading language must not take a credit line with it.

## 6. Accessibility checklist (MVP-blocking)

- AA contrast in both themes (enforced by token pairings above, and verified by computation rather than by eye — see §2).
- Every interactive element has an accessibility label — with the map's pins as a platform split worth knowing. On the web each pin is a real `<button>` carrying the market name as its `aria-label`, the disc and sprout inside it only paint (`src/components/market-map.web.tsx`). On native they are one MapLibre `symbol` `Layer` over a `GeoJSONSource` (`src/components/market-map.tsx`) — rendered pixels rather than views, so there is no element per market to label and nothing there announces a name. A symbol layer takes an image, not a component, so closing that gap means per-market annotations rather than a prop; until then the list carries the whole job on native, which is why it is a first-class equal alternative below and not a convenience.
- Text inputs declare `inputMode` so the right keyboard appears — the coordinate fields in `submit.tsx` set `inputMode: 'decimal'` — and `autoComplete` wherever a manager or the browser could helpfully fill them, which no visible field on the submit form does yet. (The honeypot's `autoComplete="off"` is the deliberate opposite and stays.)
- Anything that toggles uses `accessibilityRole="switch"` with `accessibilityState.checked`, never a pressable that merely looks switched — tag chips on all three surfaces that carry them (both filter panels and the submit form), and the `🕒 OPEN NOW` switch that leads the chip row in both of those panels. The sort control is the one that had to be corrected into this rule rather than built under it, and §4 keeps the account of what that cost — it has since left the rule legitimately, being a `button` with `expanded` that reveals four `radio`s rather than a thing that toggles. The four options are those radios, with `accessibilityState.checked` beside `aria-checked`. The sprout disc is the deliberate exception, on both screens, and it is not a toggle: it discloses a panel rather than filtering anything, so it is a `button` carrying `expanded` and `aria-expanded` (`src/components/filter-toggle.tsx`). A chip greyed out at zero also declares `disabled`, so opacity is never the only signal. Any control whose visible label is abbreviated or numeric spells its own spoken form ("Producer-owned, 2 markets") rather than leaving a screen reader to read a bare count — a rule the day chips and `WeekStrip` now follow, speaking full day names in week order, and the one `SORT` answers to by carrying the current order in its name — `Sort, Closest first`, `Sort, Name A to Z` and so on — since four visible letters cannot say where the list stands. **Where the abbreviated thing is not a control, spell it in text rather than in a label**: the counts draw the figure and its noun (`8 markets`, the figure in `Display.black`) and mount the fuller sentence off-screen, because `aria-label` names a live region without replacing the contents it announces (§4).
- List view is a first-class equal alternative to the map (screen-reader and keyboard users can do everything without touching the map).
- Respect OS font scaling up to 200% without clipped layouts; respect `prefers-reduced-motion` — the attention pulse on the map's disc, the list's staggered rows, and the map camera on both platforms, which passes a zero duration so a frame arrives rather than flying (§4). There is no standing exception left. **That last one has a cost worth naming rather than burying:** the pulse is the map's whole answer to "which control do I start from", so suppressing it leaves a reduced-motion reader with the bare mark and no hint at all — and now that the pulse recurs rather than stopping itself, that suppression is also doing more of the work of keeping the screen tolerable. A label would have served everybody; motion serves everybody who has not turned it off. The decision was made knowing that, and it is the first thing to revisit if the affordance is still not landing.
- **Touch targets carry their own size; `hitSlop` is a native-only bonus.** react-native-web's `Pressable` drops the prop outright — it appears nowhere under `dist/exports/Pressable/`, only in the legacy `Touchable` nothing here uses — so a control sized on the assumption that slop makes up the difference is that much smaller in a browser, silently, and it reads as a sizing decision rather than as an accessibility prop. Three were: the `NAME`/`NEAR` pills at 19 pt, the search box's `FIND` at 13, and the list's `↑↓` at 16. The pills carry a real `minHeight` of 24 and keep the slop for native. The other two have since gone as controls — the `↑↓` became paint inside the sort button, `FIND` was removed from the search box (§4) — and the floor each was given lives on what replaced it: 44 on the sort options, and 24 square on the box's clear `✕`, a 13 pt glyph that would otherwise be a 13 pt target. The pills and `FIND` had in fact been conformant, but only through WCAG 2.5.8's spacing exception — a geometry argument a shorter label or a wider gap would have broken, with nothing in the file saying it was load-bearing. The `FilterToggle` disc is the one knowingly left at 40 on the web (§4).
- Web: full keyboard navigation, visible focus rings (`market.green.500`, 2 px offset) — *mostly not built*: no general rule sets one, so focus is whatever the browser draws (§2). Both filter panels' search fields are the one exception and the shape the rest should take: the box is `tint` at rest — the same edge the chips beside it wear, saying "this narrows the list" rather than "this is focused" — and **focus doubles its weight, 1 pt to 2**, with the extra point taken out of the horizontal padding so nothing reflows. The weight carries it because the colour no longer can: `tint` on a `tint` resting border is a state change of zero pixels, which fails WCAG 2.4.11's 3:1 between focused and unfocused states outright. The second pixel ring goes from page colour to `tint` instead, at 7.49:1. `global.css` drops the UA outline **for that id alone**. A blanket `outline: none` is how keyboard users lose the cursor across a whole app — remove an outline only where something visible has replaced it, and never before. Space as well as Enter operates a switch — react-native-web only accepts Space for button roles, so it has to be restored explicitly (`src/lib/a11y.ts`).
- **A React Native accessibility prop is not guaranteed to reach the DOM.** react-native-web 0.21.2 silently drops `accessible`, `accessibilityState`, `accessibilityHint`, `accessibilityElementsHidden` and `importantForAccessibility`. Add the W3C attribute *alongside* the RN one — never instead of it, or native regresses. `accessibilityRole` and `accessibilityLabel` *are* forwarded, so those need no duplicate. One inversion to know about: `aria-atomic` is broken upstream in this version and never reaches the DOM at all.
- Every route sets a document title with `PageTitle` (`expo-router/head`). Screen options name the navigation chrome and do not reach the document. `PageTitle` renders on the web and nowhere else: `expo-router/head` exists on native to feed iOS handoff and Spotlight, and without a `headOrigin` (or `origin`) in the `expo-router` config plugin naming the hosted URL it throws on render — so every screen declaring a title crashed the native app. Adding handoff means setting that origin and dropping the platform guard, never removing the component.
- Anything that changes without a reload — a result count, a submission outcome — needs a live region that is **already mounted**, because a region inserted together with its text is not reliably announced.

## 7. Code conventions

- **Language:** TypeScript strict mode (`tsconfig.json`); no `any` without a `// why:` comment. The deserialization boundary is the standing exception: GeoJSON features arrive untyped and are narrowed by hand where they enter (`src/lib/markets.ts`, the repo scripts) rather than letting `any` travel inward. Narrowing there also *drops* what it doesn't recognise — `featureToMarket` filters unknown tags out rather than trusting them, so a retired tag or a fork's own vocabulary can never put a chip the UI cannot render into a filter. Anything crossing the wire is Zod's job instead of hand-narrowing, from one module: `src/lib/market-schema.ts` is imported by the validator, the intake service and the batching agent alike, so a second copy of the contract is a defect, not a convenience.
- **Formatting/linting:** `eslint-config-expo` through `npm run lint`. CI (`.github/workflows/ci.yml`) runs it beside `tsc --noEmit`, `validate-data`, `npm test` and the web export, plus a DCO check that exempts pull requests touching only `data/` ([TRD §8](./trd.md#8-testing-and-ci)). No autoformatter is configured — follow the file you're in; no style debates in review.
- **Naming:** components `PascalCase`, hooks `useCamelCase`, files kebab-case (`market-card.tsx` exports `MarketCard` — Expo convention); platform splits via `component.web.tsx`.
- **Structure:** screens in `src/app/` stay thin (layout + navigation); logic lives in `src/lib/` and is unit-tested without rendering. Components receive data via props, not global fetches. That split is what makes the suite in `test/` possible: it exercises `src/lib/` and `server/` directly and mounts nothing, so anything you push into a component becomes untestable by construction. A helper only a hook can reach is a helper nothing can check — export it.
- **Tests:** `node:test` + `node:assert/strict` through tsx (`npm test`), files in `test/`. No test framework is installed and none should be added. Name a test after the promise it keeps — "a market with no website is flagged for a reviewer, not dropped" — never "it works". Test this project's decisions, not zod's or Node's, and never assert on the clock, the network or a running service. Read policy numbers from `intake.config.json` rather than restating them; a test that hard-codes a threshold keeps passing after someone changes the committed policy ([TRD §8](./trd.md#8-testing-and-ci)).
- **Theming:** all colors/spacing/type through the token file (`src/constants/theme.ts` — `Colors`, `Spacing`, `Radii`, `Elevation`, `Display`, `Fonts`, `MaxContentWidth`, and `MapFitPadding`, composed from `Spacing` so a camera fit keeps a pin clear of the controls floating over the map). A hardcoded hex in a component is a review-blocker.
- **Vocabularies:** the tag list is a closed set in `src/constants/tags.ts`, imported by both the app and `scripts/validate-data.ts` so the data and the UI cannot drift and CI rejects a tag the app has no label for. A tag string typed straight into a component is the same review-blocker a raw hex is, and for the same reason: the second place a value lives is where the two start disagreeing.
- **State:** local `useState` plus small hooks — `useTheme()` resolves the OS color scheme to a palette, `useUserLocation()` owns the permission dance. The submit form is screen-local `useState` and stays that way — a half-typed submission that follows you between tabs is one you cannot clear. **The narrowing is not, any more.** Tag selections and the search text live in `FiltersProvider` (`src/hooks/use-filters.tsx`) and are shared by the map and the list.

  That reverses this file's own rule, so the reasoning belongs here rather than in a commit nobody re-reads. The rule was written when the two screens had little in common; they now show the same dataset through the same components — one `TagFilter`, one `MarketSearch`, one closed vocabulary. Narrowing to producer-owned on the map and meeting fifteen pins again on the list does not read as a fresh start, it reads as the two tabs disagreeing about what you asked for.

  The old rule's hazard — "a filter that survives leaving the screen is a filter someone forgets is on" — is real, and it is answered on screen rather than by architecture: the sprout wears a dot whenever anything is narrowing, on **both** screens, and opening either panel shows the query and the chips in plain sight. A filter you can see is not one you forget. What did **not** move matters as much: nothing is persisted, so a relaunch is still a clean slate; sort key and direction stay on the list because the map has no order; `🕒 OPEN NOW` is shared now and was not: it stayed on the list while the map had no such control, since a pin filtered by something with nothing on that screen to see or unset is the forgotten-filter hazard in its purest form. The map's filter panel carries the same switch as of UAT, so the objection retired and the state moved into `useFilters` with the tags and the query — two tabs answering one question differently is the disagreement that hook exists to end. Nor does a geocoded origin travel, because it means "sort from here" on one screen and "look here" on the other. TanStack Query owns the dataset, and only the dataset: `useMarkets()` takes no arguments because there is no second source to merge and no option worth offering. The app's two other network calls stay outside it deliberately — the intake POST (`src/lib/submit.ts`) is a one-shot write with nothing to cache, and the address lookup (`src/lib/geocode.ts`) keeps its own bounded cache and one-second interval because Nominatim's usage policy sets both numbers and one limiter has to span two endpoints, which is not a shape a per-query `staleTime` expresses. The providers at the root are `QueryClientProvider`, expo-router's `ThemeProvider` for navigation chrome, and `FiltersProvider`. The bar for a fourth stays high. No Redux unless complexity forces it.
- **Nothing in the client is a permission.** There is no session, no role and no privileged screen — every screen shows the same dataset to everyone, and the only write is an anonymous POST the service is free to refuse ([TRD §7](./trd.md#7-security)). Don't reintroduce a "hidden unless" branch; if a surface needs guarding, the guard belongs on the server or the change belongs in a pull request.
- **The intake service is app-shaped, not backend-shaped** (`server/`): plain Node, no framework, no ORM, and no state it cannot afford to lose — the queue is operational, `data/markets.json` is canonical. It shares the schema module with the app rather than keeping its own copy, and every tunable number (batch size, rate limits, dedupe radius, the flag list) lives in `intake.config.json` where changing it is a reviewable diff, never as a constant in `server/`.
- **Comments:** explain *why*, not *what*. Data-shape assumptions get a link to the contract — the feature schema is [TRD §2](./trd.md#2-the-dataset-is-the-product). Section numbers in those links are real references, not decoration: renumbering the TRD means repointing them in the same pass, or the next reader follows a comment to a section that no longer says what it cites.
- **Commits/PRs:** Conventional Commits (`feat:`, `fix:`, `data:`, `docs:`), scope optional (`fix(map):`). Dataset PRs (`data:`) have to pass `npm run validate-data`, which CI runs on every PR. That PR *is* the publication process — a new market, a correction, a tag all arrive the same way ([TRD §4](./trd.md#4-the-submission-pipeline)) — so a `data:` review is the last place a mistake is cheap, and the conventions above are how it stays reviewable.
